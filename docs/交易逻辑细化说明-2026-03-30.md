# 交易逻辑细化说明（前端下单 -> 后端撮合成交）

> 基于现有 PRD / 需求文档 / 当前代码实现整理。  
> 目标：将“前端下单、后端撮合、异常防护、状态回传、结算落账”形成可执行规则。

## 1. 交易链路总流程（V1）

1. 前端录入订单（股票、方向、价格、数量、订单类型）。
2. 前端本地预校验（最小价、手数、空值、防抖）。
3. 前端提交到 `POST /api/v1/trade/orders`（携带 `X-User-Id`、`X-Lang`、`lang`）。
4. 后端做业务校验（交易时段、白名单、停牌、±20 ticks、20 笔买单上限、5 笔限价轮候上限、持仓可卖量等）。
5. 后端执行重复提交拦截（同用户同签名短窗口去重）。
6. 通过校验后生成订单，进入撮合判断：
   - 市价单：可交易时段内即时成交；
   - 限价单：满足即时成交条件则成交，否则进入轮候。
7. 返回订单结果（`orderId/status/validity/lang`）。
8. 前端进入“提交成功/订单详情/交易记录”后续流程。
9. 后端按已成交订单进入 T+2 结算逻辑（当前版本为营业日简化实现）。

## 2. 前端侧规则（防抖 + 重复提交 + 用户体验）

## 2.1 输入校验（提交前）
- 股票必须可交易（白名单范围）。
- 价格：
  - 买入不得低于 `HK$0.05`
  - 卖出不得低于 `HK$0.01`
- 数量必须是每手股数整数倍。
- 非法输入直接前端拦截，不发请求。

## 2.2 防抖与重复点击保护
- 提交按钮在请求进行中置灰（`submitPending=true`），禁止二次点击。
- 弹窗确认与提交动作分离，避免误触连续下单。
- 同一订单改价/撤单流程中，互斥处理（改单中不可重复改单）。

## 2.3 失败分级反馈
- 参数错误：直接显示业务可读提示（如最小价、手数不符）。
- 业务拦截：显示后端返回语义化错误（如超 20 笔、停牌、超 ±20 ticks）。
- 系统失败：统一降级提示，并保留重试入口。

## 3. 后端侧规则（金融级核心校验）

## 3.1 交易准入校验顺序（建议保持顺序稳定）
1. 请求合法性：用户/股票/方向/类型/价格/数量。
2. 标的校验：是否白名单、是否停牌。
3. 时段校验：港股交易时段 `09:30-12:00`、`13:00-16:00`；市价单仅交易时段允许。
4. 价格校验：买卖底价 + 限价单 ±20 ticks。
5. 数量校验：必须整手。
6. 账户规则：卖出可用持仓、单日买入上限 20 笔、限价轮候上限 5 笔。
7. 幂等/去重：同签名短窗口重复提交拦截。

## 3.2 去重（已落地）
- 签名维度：`userId|stockCode|direction|orderType|price|quantity`
- 时间窗：`1500ms`
- 命中后直接拒绝，避免“网络重试/连点”造成重复下单。
- 强幂等增强：支持可选请求头 `X-Idempotency-Key`
  - 同 `(userId, idempotencyKey)` + 同请求体：返回同一个 `orderId`（避免客户端重试重复落单）
  - 同 `(userId, idempotencyKey)` + 不同请求体：返回 `400`（拒绝 key 复用污染）

## 3.3 订单状态机（V1）
- `PENDING`：排队中（未成交）
- `PARTIAL_FILLED`：部分成交
- `FILLED`：完全成交
- `CANCELED`：已取消
- `REJECTED`：拒单（校验失败或不可执行）

状态迁移约束：
- `PENDING/PARTIAL_FILLED -> CANCELED` 允许；
- `FILLED/CANCELED/REJECTED` 不可再撤单或改单；
- 改单实际流程：原单取消 + 新单创建（限价单限定）。

## 4. 撮合逻辑细化（V1 简化撮合）

## 4.1 成交判断
- 市价单：交易时段内默认立即成交，成交价取当前价。
- 限价单：
  - 买单：委托价 >= 当前价，可即时成交；
  - 卖单：委托价 <= 当前价，可即时成交；
  - 否则进入排队。

## 4.2 排队规则
- 仅限价单进入轮候队列。
- 每账户最多 5 笔轮候中限价单。
- 停牌时不得新增买卖，仅允许取消未成交挂单。

## 4.3 异常场景处理
- 下单/改单/撤单/撮合写入：当前实现要求 DB 持久化成功，否则直接抛业务异常返回，不再做订单内存兜底。
- 订单查询：当前走 DB 主链路（按用户或订单 ID 查询），不再合并本地订单缓存。
- 联调测试：`/api/v1/trade/quote/debug-push?forceMatch=true` 可在非交易时段触发撮合，用于回归验证挂单到成交链路。
- 行情乱序保护：`MarketDataRealtimeService` 会丢弃时间戳落后/相等的行情（`accepted=false`），并且不触发撮合，避免旧行情回放覆盖新报价。

## 5. 结算逻辑（T+2）

- 已成交订单进入 T+2 结算视图。
- 当前实现：通过 `TradingCalendarService.addTradingDays(tradeDate, 2)` 计算（已支持周末 + 可配置节假日）。
- 后续增强：接入香港交易日历（节假日/半日市）后再升级真实 T+2 落账。

## 6. 多语一致性规则（UI 与接口同语言）

- 前端统一发送：`X-Lang`（header）+ `lang`（query）。
- 后端统一解析优先级：`X-Lang` > `lang` > `Accept-Language` > 默认 `zh-Hant`。
- 接口响应包含 `lang` 字段（交易/账户/榜单/首页核心接口）。
- 错误消息通过统一异常处理按语言本地化。

## 7. 隐藏问题清单与预防策略

1. **连点导致重复订单**
   - 前端按钮禁用 + 后端短窗口去重双保险。
2. **前端重试导致重复提交**
   - 已支持 `X-Idempotency-Key`；建议前端每次提交生成并复用一次 key 直到请求完成，避免网络重试重复下单。
3. **改单与撤单并发冲突**
   - 建议后续引入订单版本号（乐观锁）避免写冲突。
4. **缓存/内存与数据库不一致**
   - 订单主链路已去掉内存兜底，但账本仍有内存态；后续建议账本落库并加审计对账。
5. **交易时段边界误差**
   - 建议统一使用香港时区时钟源，避免客户端本地时间偏差。
