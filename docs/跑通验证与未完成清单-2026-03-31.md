  - 后端服务监听 `:8080`（已重启为本轮最新代码）
- 请求验证（`X-User-Id=u_smoke_3103`）：
  1. 三语账户：`GET /api/v1/account/profile?lang=zh-Hant|zh-Hans|en` -> 均 `code=200`，`data.lang` 与请求语言一致
  2. 语言+跨域：`OPTIONS /api/v1/account/profile`（preflight）-> `Access-Control-Allow-Headers` 包含 `lang,x-user-id`
  3. 报价：`GET /api/v1/trade/quote/00700?lang=en` -> `code=200`，`source=MOCK`
  4. 预览：`POST /api/v1/trade/orders/preview?lang=en` -> `code=200`，返回 `language=en` 且 `lang=en`
  5. 下单：`POST /api/v1/trade/orders?lang=en` -> `code=200`，状态 `PENDING`（当前时段为非交易时段，返回 `NEXT_TRADING_DAY_CLOSE`）
  6. 活动订单：`GET /api/v1/trade/orders/active?lang=en` -> `code=200`，可查到挂单
  7. 撤单：`POST /api/v1/trade/orders/{orderId}/cancel?lang=en` -> `code=200`，状态 `CANCELED`
  8. 历史：`GET /api/v1/trade/orders/history?lang=en` -> `code=200`，可查到撤单记录
  9. 防重复提交：同签名 1500ms 内二次下单 -> 首次 `code=200`，二次 `code=400`（Duplicate order submission）
  10. 强制撮合联调：`POST /api/v1/trade/quote/debug-push?forceMatch=true`（非交易时段）-> 挂单可被撮合，订单状态从 `PENDING` 变为 `FILLED`
  11. 幂等键回放：`X-Idempotency-Key` + 相同请求重试 -> 返回同一 `orderId`；同 key 不同请求 -> `code=400`
  12. 行情乱序保护：先推新行情再推旧行情到 `debug-push` -> 新行情 `accepted=true`，旧行情 `accepted=false` 且 `reason=STALE_MARKET_DATA`

## 3. 当前未完成（必须继续做）

### 3.1 行情与撮合微结构

1. 行情源仍有 mock 依赖：`MockDataService` 提供静态股票池、静态价格、停牌标记。
2. 报价在无实时盘口时会合成 5 档深度（模拟量），非真实 order book。
3. 撮合存在单价兜底路径（无盘口时按单价/中间价），非完整订单簿逐笔撮合。
4. AOB protobuf 解码仍基于字段启发式解析，需与线上 schema 严格对齐并补全异常场景。

### 3.2 一致性与持久化

1. 订单主链路（下单/改单/撤单/查询）已改为 DB 优先，不再使用本地订单 in-memory fallback。
2. `AccountLedgerService` 已补账本/持仓/结算落库表与 Mapper；当前仍是“内存 + DB 混合态”（DB 异常时回退内存），尚未完成纯持久化切换与历史数据回填方案。
3. 下单去重为 Redis 优先，但 Redis 不可用时仍会降级到本地内存去重。
4. 缺少“行情消息去重 + 顺序控制 + 重放防护”的完整闭环。

### 3.3 交易规则细项

1. 交易日历已支持周末+配置假日，但半日市、临时停市、竞价阶段规则未完整落地。
2. 尚未建立“交易所级别状态机”文档到代码的一一映射（尤其竞价/连续交易切换）。

## 4. 下一阶段落地顺序（建议）

1. **先落库再增强撮合**：先把账本与结算从内存迁移到持久层，消除重启丢态风险。
